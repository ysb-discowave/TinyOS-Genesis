v0.1 实际怎么装包：romfs 内置路线 ✅

这是 v0.1 真正在用的做法，已经可用。包不是用 pkg 命令装的，而是随镜像一起编译进只读文件系统 romfs：用户程序由宿主机脚本交叉编译成 .TNCR，再打进 romfs，内核启动时挂载，/bin/*.TNCR 直接可执行。

  1. tools/build_users.py 交叉编译用户程序 → .TNCR
  2. →
  3. tools/mkromfs.py 打包压缩进 romfs
  4. →
  5. kernel boot 挂载 romfs 到 VFS
  6. →
  7. /bin/*.TNCR 直接可执行

构建入口（宿主机侧）

# 交叉编译用户态 TNCR 程序（tinysh / lua / 网络组件 …）
python tools/build_users.py

# 把 .TNCR 打进只读 romfs（tools/mkromfs.py 在内部被调用）
# 内核源码在 src/kernel/；构建入口是 build.ps1
powershell -ExecutionPolicy Bypass -File build.ps1

安装向导也能勾选组件 ✅

安装器 src/kernel/install.c 的向导第 3 步「Software」可以让用户勾选要写入磁盘的组件（例如 JVM.TNCR 运行时）；向导按勾选决定是否把它写盘。这条路线是真实的、已实现的。

一条命令就能用，靠的是 romfs 不是 pkg

lua、tinysh、sshd、CC、EDIT 等之所以「装好即用」，是因为它们已经作为 .TNCR 躺在 romfs 的 /bin 下，内核挂载后直接可执行。这与 pkg 命令无关 —— pkg 目前不存在。

包结构规范（来自 docs/pkg_spec.md）🚧

下面是规范文档定义的包布局与 manifest 字段。规范本身已经写清楚，但 pkg 命令与仓库里的大部分包内容尚未落地 —— 所以规范是「已定义」，落地是「规划中」。

标准目录布局

packages/xxx/
├─ xxx.manifest      # 包描述与构建规则
└─ src/              # 源码目录

manifest 字段

manifest 字段表（字段名与类型为英文，固定不变）
字段 类型 说明
name string 包名，必须与目录名一致。
version string 版本，统一跟随发行版（例如 v0.1）。
description string 一句话描述。
dependencies list 依赖包名列表，可为空。
min_compiler string 最低编译器版本，例如 tncr>=0.1。
sha256 string 产出 .tncr 的 SHA256 校验，安装时校验（当前多为占位）。
build object 构建指令：入口 entry、输出 .tncr 路径 output、参数 cmd。

真实示例：packages/tinysh/tinysh.manifest（逐字）✅

这是仓库里目前唯一内容完整的包，其 manifest 逐字如下。注意 sha256 写的是 __BUILD_FILL__，是一个还没填的占位符（见「待补齐」一节）。

name: tinysh
version: v0.1
description: TinyOS Genesis 默认 Shell（/bin/tinysh.tncr）
dependencies: []
min_compiler: tncr>=0.1
sha256: __BUILD_FILL__
build:
  entry: src/tinysh.c
  output: /bin/tinysh.tncr
  cmd: zig cc -std=c11 -DTINYOS_USER -o tinysh.tncr src/tinysh.c src/kernel_api_tinyos.c

官方软件源 🚧

规范文档给出的官方源是一个 GitHub Raw 地址。下面原样列出，并提示一个大小写不一致的细节。

https://raw.githubusercontent.com/ysb-discowave/TinyOS-Genesis/main/packages

⚠️ 大小写不一致：以实际仓库为准

规范文档里写的是小写 tinyos-genesis，但实际远端仓库名是 TinyOS-Genesis（首字母大写）。GitHub Raw 的仓库段在多数情况下大小写不敏感，但为稳妥起见，请以实际仓库 TinyOS-Genesis 为准，或直接在浏览器/工具里确认该地址可访问。

注意：上面是「规划中」的官方源（pkg 命令要消费它）。v0.1 实际交付的包来自 romfs 内置，不从这个 URL 拉取。
